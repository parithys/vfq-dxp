## Purpose
Shows a Siebel/Oracle-based CRM agent (Open UI Desktop) how to run the "Cross Sales" guided journey against an **existing** customer/contact (identified by Qatari ID) to present targeted cross-sell offers, accept a "New Postpaid" offer, and carry the agent straight into the standard New Postpaid provisioning wizard (Contact → Address → Account → Billing → Number Selection → SIM Serial → Plan → Payment → CAF → Activity) to complete a brand-new postpaid line for that same customer. It also shows a secondary linked modification order that adds a data add-on to one of the customer's other existing lines as part of the same transaction.

**Overall flow summary — where cross-sell fits relative to a plain New Postpaid sale:** Cross Sales is entered via its own top-level nav icon and its own mini-wizard (Contact → Offers) run against an *existing* customer. Step 2 ("Offers") is the differentiator: it surfaces system-generated, campaign-driven offers (here "New MNP" and "New Postpaid", both under CampaignCode C000009053) with Accept/Interested/Reject/Close actions — a plain New Postpaid journey has no such offer-selection step. Once the agent accepts the "New Postpaid" offer, control passes directly into the same underlying New Postpaid provisioning wizard used for a standalone sale (Contact re-confirm → Address → Account → Billing → Number Selection → SIM Serial → Plan → Payment → CAF → Activity), with the plan pre-oriented toward "New Plus Max India BIA Promotion". The transaction also produced a secondary Modification order that added a small data bundle to one of the customer's other existing lines, suggesting the Cross Sales engine can bundle in incremental add-ons to existing services alongside the new activation.
