## Journey Overview

Catalogue #124 "Resume Suspension" is the reversal counterpart of catalogue #117 "PMN Suspension" (Park My Number). A customer (or account) that has been placed into the PMN "manual suspension" state — a 35 QAR, four-month upfront-paid low-benefit plan with credit limit forced to zero — needs that state undone so the account returns to its normal plan, normal credit limit, and normal service availability.

Per the catalogue description, this is done today (Vanilla/Open UI desktop channel) by a back-office agent **manually locating the existing PMN Modification order and creating a new Modify order that customizes/reverses it** — restoring the prior plan and credit limit. There is no dedicated guided-journey (desktop or tablet) walkthrough for this in the corpus; it is a Vanilla/back-office administrative action, consistent with row 117's own channel ("Action through Vanilla (Open UI desktop)").

**Evidentiary status:** The PMN *suspend* mechanism (plan economics, credit-limit rule, role restriction, ticket-driven governance, system-of-record) is directly and richly evidenced. The *resume*-specific steps are **not** independently walked through anywhere in the corpus — they are structurally inferred as the logical reversal of the documented suspend mechanism, consistent with the catalogue's own one-line description ("creating a Modify order and customizing it"). This distinction is flagged step-by-step below.

## Exception Handling

- **Role not authorized** — **[INFERRED, symmetric to suspend-side rule]** ticket cannot be actioned by the requesting agent; presumably reassigned to a permitted role. Not documented for the resume path specifically.
- **No PMN order found** — **[INFERRED]** if the account is not actually in a PMN/manually-suspended state, there is nothing to reverse; the ticket would be rejected/closed. Not documented.
- **Automatic resumption is explicitly out of scope** — **[EVIDENCED]**: "automatic resumption has been stopped" (01:17:16/01:24:34). This isn't an exception in the resume flow itself, but a hard constraint ruling out any auto-triggered (e.g., time-based, payment-based) resume path — every resume must be a manual, ticketed, role-gated action.
- **Customer travel / credit-limit override while parked** — **[EVIDENCED, suspend-side]**: "customers travelling may need it changed" (01:23:12) refers to a credit-limit exception *during* the parked state, not a resume step, but is included because it shows credit-limit handling is not perfectly rigid — some manual override capacity exists in the parked state, and by extension could plausibly apply during resume order customization. Flagged as adjacent context, not a resume-step per se.
